# Voice for Ask Guardian — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A customer can hold a button and ask Ask Guardian a question out loud, have the answer read back if they want it, and leave a wallboard running that says a new critical alert instead of only drawing a toast nobody is close enough to read.

**Architecture:** ElevenLabs does both halves, and the hub is the only thing that talks to it — the app's CSP is `default-src 'self'` with no third-party origin, so the browser cannot reach the vendor and must not try. A transcript comes back to the browser and lands in the chat composer's **textarea**, not in a turn, so voice inherits the existing approval model whole and gains no authority of its own. Playback goes through Web Audio rather than an `<audio>` element, which sidesteps `media-src` without relaxing the policy.

**Tech Stack:** FastAPI + `httpx` (already a declared hub dependency), pydantic v2, React 18 + TypeScript, `MediaRecorder` and `AudioContext`, vitest, pytest.

**Spec:** `docs/superpowers/specs/2026-09-22-voice-design.md`

## Global Constraints

- **Hub tests run from `hub/`**: `cd hub && .venv/bin/pytest`. Web from `web/`: `npm test`, `npm run lint`, `npm run build`. Never run one package's suite from another's directory.
- **Never assert wall-clock.** No `time.time()` deltas, no `elapsed < N`. There is no time-budget feature in this plan, so there is no honest exception to the rule.
- **Comments explain _why_, not _what_.** A one-line `# start the recorder` is noise in this codebase; a paragraph explaining a trap is the house style. Every docstring in this plan is part of the deliverable — type it, do not summarise it.
- **Commit subjects are a sentence describing the user-visible behaviour change**, present tense, sentence case. No `feat:`/`fix:` prefixes. Exception: a docs-only commit may use `docs:`, which recent history does.
- **Stage by explicit path.** Other sessions share this checkout; never `git add -A` or `git add .`.
- **End every commit message with:** `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`
- `web/src/types.ts` is contract-tested against the pydantic models by `hub/scripts/check_types.py` and `hub/tests/test_contracts.py`. A field added to one without the other fails the suite.
- **Nothing in this plan may write `trusted` or `label`.** `hub/tests/test_warrant_rule.py` enforces it.
- Vendor endpoints, verified 2026-09-22: `POST https://api.elevenlabs.io/v1/speech-to-text` (multipart, `model_id` + `file`, header `xi-api-key`) and `POST https://api.elevenlabs.io/v1/text-to-speech/{voice_id}` (JSON `text`/`model_id`/`output_format`, returns audio bytes).

- [ ] **Step 4: Write the module**

Create `hub/guardian_hub/voice.py`:

```python
"""ElevenLabs speech-to-text and text-to-speech, and the only place either runs.

Why a module rather than a call in the router: the app is served under
`default-src 'self'` with no third-party origin (`deploy/nginx-api.conf.tmpl`),
so a browser cannot reach api.elevenlabs.io at all and every byte in both
directions goes through the hub. That began as a constraint and is the right
answer anyway -- the key never leaves the server, and a customer on a segment
whose only egress is api.guarder.io still has a working dashboard.

Failure discipline is `chat/providers.py`'s, for its reason. A vendor having a
bad afternoon must not become a 500 on a dashboard somebody opened *because*
their network is down. Nothing here raises: `transcribe` returns "" and
`speak` returns b"" on anything that goes wrong, and the caller decides what
to say about it.

The key is never logged. `_why` exists to make that structural rather than
careful -- the vendor's error bodies are plain JSON about accounts and quotas
and never echo the key we sent, so status and body are safe to log; the
request headers would not be, and nothing here logs them.
"""
from __future__ import annotations

import logging

import httpx

from .config import settings

log = logging.getLogger(__name__)

STT_URL = "https://api.elevenlabs.io/v1/speech-to-text"
TTS_URL = "https://api.elevenlabs.io/v1/text-to-speech/{voice_id}"
TIMEOUT_S = 30.0

#: The upload types the hub will forward, pinned rather than passed through.
#: Safari and Chrome hand `MediaRecorder` output back under different types so
#: the set has to be explicit; what it must not be is a client-supplied header
#: forwarded unread, which would make the vendor our input validator.
ALLOWED_AUDIO = {"audio/webm", "audio/ogg", "audio/mp4", "audio/mpeg", "audio/wav"}


def ready() -> bool:
    """True when voice can run at all -- both halves, not one.

    Mirrors `chat/providers`' `_groq_ready`: the credential's presence is the
    switch. The voice id is part of it because a key without one transcribes
    and cannot speak, and a UI that shows a speaker which always 502s is worse
    than one that shows no speaker.
    """
    return bool(settings.elevenlabs_api_key and settings.elevenlabs_voice_id)


def _headers() -> dict[str, str]:
    return {"xi-api-key": settings.elevenlabs_api_key}


def _why(exc: Exception) -> str:
    """A safe-to-log one-liner for a vendor failure.

    Same rule as `chat/providers._describe_failure`: the response body is the
    vendor's own account/quota JSON and never contains the key we sent, so it
    is safe; the request headers are not, and are never passed here.
    """
    if isinstance(exc, httpx.HTTPStatusError):
        return f"HTTP {exc.response.status_code}: {exc.response.text[:200]}"
    return f"{type(exc).__name__}: {exc}"


def transcribe(data: bytes, content_type: str) -> str:
    """Audio in, one line of text out. "" when voice is off or anything fails."""
    if not ready() or not data:
        return ""
    try:
        r = httpx.post(STT_URL, headers=_headers(), timeout=TIMEOUT_S,
                       data={"model_id": settings.elevenlabs_stt_model},
                       files={"file": ("clip", data, content_type)})
        r.raise_for_status()
        text = r.json().get("text")
        return text.strip() if isinstance(text, str) else ""
    except Exception as exc:
        log.warning("speech-to-text failed: %s", _why(exc))
        return ""


def speak(text: str) -> bytes:
    """Text in, MP3 bytes out. b"" when voice is off or anything fails."""
    if not ready() or not text.strip():
        return b""
    try:
        r = httpx.post(TTS_URL.format(voice_id=settings.elevenlabs_voice_id),
                       headers=_headers(), timeout=TIMEOUT_S,
                       json={"text": text,
                             "model_id": settings.elevenlabs_tts_model,
                             "output_format": "mp3_44100_128"})
        r.raise_for_status()
        return r.content
    except Exception as exc:
        log.warning("text-to-speech failed: %s", _why(exc))
        return b""
```

Create `hub/guardian_hub/routers/voice.py`:

```python
"""Guardian's ear and mouth -- the only two routes that touch the voice vendor.

Both are session-authenticated dashboard routes. Neither reads a row and
neither writes one: `transcribe` turns audio into text and forgets the audio,
`speak` turns text into audio and forgets the text. That is why there is no
audit row here and no `Edit` -- there is no state change to attribute.

**Nothing in this file carries authority, and that is the whole design.** A
transcript goes back to the browser and lands in the chat composer's
*textarea*, where the customer reads it and presses send like any other
sentence. So an approval-tier repair still comes back as a `ChatProposal`
whose single-use token only the on-screen button can spend, and a misheard
sentence gets edited instead of executed. Do not add a `confirm_token` here,
and do not route a transcript straight through `chat.run_turn` to save a hop:
the hop IS the clamp. Guardian's approval tier is token-bound precisely
because an intention has to be attributable, and a sentence spoken in a
waiting room is not attributable to anyone.
`tests/test_voice_authority.py` fails if that stops being true.

Push-to-talk, never a wake word. A wake word means this hub receives audio
from a medical practice's waiting room continuously; the browser's microphone
indicator being lit for exactly as long as a button is held is the only
honest signal a customer can actually check.

`speak` is a POST even though a GET would let an `<audio>` element point
straight at it, because the text is a sentence about somebody's network and a
GET would put it in a URL, an access log and a browser history. The web plays
it through Web Audio rather than an element anyway -- the app's CSP is
`default-src 'self'`, under which a `blob:` URL is not `'self'` -- so the
element was never available to lose.
"""
from __future__ import annotations

from fastapi import APIRouter, Depends, File, HTTPException, Response, UploadFile
from pydantic import BaseModel, Field

from .. import ratelimit, voice
from ..deps import require_role

router = APIRouter(prefix="/api/v1", tags=["voice"])

VIEWER = Depends(require_role("viewer"))

#: A held button cannot legitimately produce more than this. The vendor
#: accepts 5 GB, which is not a ceiling this product wants to inherit, and an
#: unbounded upload on a session route is a memory-exhaustion primitive.
MAX_CLIP_BYTES = 10 * 1024 * 1024

#: Comfortably above a verdict sentence plus a "Next:" line, and far below
#: anything that would bill a surprise -- TTS is charged per character, and
#: what the app speaks is deliberately the conclusion and not the whole reply.
SPEAK_CHARS_MAX = 600

#: Generous for a human pressing a button, tight enough that a stuck loop in
#: the browser cannot turn a session into a bill.
RATE = (30, 60)


class SpeakIn(BaseModel):
    text: str = Field(..., min_length=1, max_length=SPEAK_CHARS_MAX)


def _guard(user_id: str) -> None:
    """The two checks both routes share: voice exists, and this user is not
    hammering it. 503 rather than 404 when unconfigured, because the route is
    real and the capability is missing -- and the web hides the controls
    entirely on `OverviewPayload.voice`, so reaching here at all means either
    a stale tab or somebody with curl."""
    if not voice.ready():
        raise HTTPException(503, "Voice is not configured on this hub.")
    if not ratelimit.allow(f"voice:{user_id}", *RATE):
        raise HTTPException(429, "too many voice requests -- wait a minute and try again")


@router.post("/voice/transcribe")
async def transcribe(file: UploadFile = File(...), ctx=VIEWER) -> dict:
    user, _tenant, _role = ctx
    _guard(user.id)

    # The bare type only. Chrome sends `audio/webm;codecs=opus` and Safari
    # sends `audio/mp4`, so matching the whole header would reject the single
    # most common real upload -- and accepting the header unread would make
    # the vendor our input validator.
    ctype = (file.content_type or "").split(";")[0].strip().lower()
    if ctype not in voice.ALLOWED_AUDIO:
        raise HTTPException(415, f"unsupported audio type: {ctype or 'unknown'}")

    # One byte past the cap, so an oversize body is detected without ever
    # holding all of it.
    data = await file.read(MAX_CLIP_BYTES + 1)
    if len(data) > MAX_CLIP_BYTES:
        raise HTTPException(413, "that clip is too long")

    return {"text": voice.transcribe(data, ctype)}


@router.post("/voice/speak")
def speak(body: SpeakIn, ctx=VIEWER) -> Response:
    user, _tenant, _role = ctx
    _guard(user.id)

    return Response(content=audio, media_type="audio/mpeg",
```

```ts
import { useCallback, useRef, useState } from "react";

/** The app's only microphone and the app's only loudspeaker.
 *
 *  Three surfaces use this — the chat composer's mic, the chat header's
 *  speaker toggle, the wallboard's — and there is exactly one implementation,
 *  for the reason `components/ApiTokenPanel` has one: a second copy would be
 *  a second place to get microphone release and the AudioContext gesture rule
 *  right, and the day they drifted a customer would find out before we did.
 *
 *  Neither half talks to the voice vendor. It could not: the app is served
 *  under `default-src 'self'` with no third-party origin, so `api.elevenlabs.io`
 *  is unreachable from here and every byte goes through the hub. That is also
 *  why playback does not use an `<audio>` element — `media-src` falls back to
 *  `default-src 'self'` and a `blob:` URL is not `'self'`. Web Audio is not
 *  subject to `media-src`, so it works with no CSP change, and do not "fix"
 *  this later by adding `media-src 'self' blob:` to the nginx template.
 *
 *  **Trap one: the gesture rule is about the context's lifetime, not about a
 *  click having happened.** An `AudioContext` must be created or resumed
 *  inside a user gesture, and a browser may suspend an idle one at any point
 *  afterwards. That is invisible in a fresh tab and fatal on a wallboard,
 *  which is the only surface here that is ever idle for hours: the toggle is
 *  clicked once when the screen is set up and the first CRIT can arrive long
 *  after, by which time the context can be `suspended` and a `resume()`
 *  outside a gesture can be refused outright. So there is ONE module-level
 *  context, `enableAudio()` creates or resumes it from inside the toggle's
 *  own handler, and `speak()` returns false rather than pretending when the
 *  context is not running. Callers turn their own toggle back off on false —
 *  a lit speaker icon over a silent room is a wall display lying about being
 *  audible, which is the same failure as a dashboard that goes blank when the
 *  uplink dies.
 *
 *  **Trap two: a stopped MediaRecorder does not release the microphone.** The
 *  browser's recording indicator stays lit until every track is stopped, so
 *  `stopTracks` runs on the error path as well as the success path. A security
 *  product that appears to be listening when it is not is a worse bug than one
 *  that fails to listen. */

let ctx: AudioContext | null = null;
let playing: AudioBufferSourceNode | null = null;

/** Create or resume the single audio context. **Call only from inside a user
 *  gesture handler** — a click, a pointerdown, a keydown.
 *
 *  Returns whether a usable context now exists, NOT whether it is already
 *  running: `resume()` is asynchronous, so reading `state` on the next line
 *  would report "suspended" in a real browser and "running" against any mock
 *  that resolves eagerly — a test that passes for the wrong reason. `speak()`
 *  does the running check at play time, which is the moment that matters, and
 *  a caller whose first `speak()` comes back false turns its own toggle off.
 *  So the toggle goes on optimistically and corrects itself; it never claims
 *  to be audible on the strength of a state read that cannot be true yet. */
export function enableAudio(): boolean {
  try {
    if (!ctx) ctx = new AudioContext();
    if (ctx.state === "suspended") void ctx.resume();
    return ctx.state !== "closed";
  } catch {
    // No Web Audio at all (an old browser, a locked-down embed). Silence is
    // the whole degradation: the caller hides its control.
    return false;
  }
}

export function audioReady(): boolean {
  return ctx !== null && ctx.state === "running";
}

export function stopSpeaking(): void {
  try {
    playing?.stop();
  } catch {
    // Already ended. `stop()` on a finished source throws in some engines and
    // there is nothing to do about it.
  }
  playing = null;
}

/** Say `text` out loud. Resolves false when nothing was played, which the
 *  caller may surface however it likes — usually by turning its toggle off. */
export async function speak(text: string): Promise<boolean> {
  const body = text.trim();
  if (!body || !ctx || ctx.state !== "running") return false;
  try {
    const res = await fetch("/api/v1/voice/speak", {
      method: "POST",
      credentials: "include",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ text: body }),
    });
    if (!res.ok) return false;
    const buf = await ctx.decodeAudioData(await res.arrayBuffer());

    // One voice at a time. Two of the three callers can fire in bursts — a
    // wallboard taking four CRITs in a minute, a reader hitting the speaker
    // on a fresh answer while the last is still going — and without this the
    // browser happily plays both at once.
    stopSpeaking();

    const src = ctx.createBufferSource();
    src.buffer = buf as AudioBuffer;
    src.connect(ctx.destination);
    src.onended = () => { if (playing === src) playing = null; };
    playing = src;
    src.start();
    return true;
  } catch {
    return false;
  }
}

/** The MIME types we ask `MediaRecorder` for, in order. The hub pins the same
 *  set (`voice.ALLOWED_AUDIO`) and rejects anything else with a 415, so asking
 *  for a type the hub will refuse is a round trip wasted. */
const PREFERRED = ["audio/webm", "audio/mp4", "audio/ogg"];

function pickMime(): string {
  const Rec = (globalThis as { MediaRecorder?: { isTypeSupported?(t: string): boolean } }).MediaRecorder;
  if (!Rec?.isTypeSupported) return "";
  return PREFERRED.find((t) => Rec.isTypeSupported?.(t)) ?? "";
}

export type Dictation = {
  recording: boolean;
  error: string;
  start: () => void;
  stop: () => void;
};

/** Push-to-talk. `start` on press, `stop` on release; the transcript arrives
 *  through `onText`.
 *
 *  Push-to-talk and never a wake word. A wake word would mean the hub
 *  receiving audio from a medical practice's waiting room continuously; the
 *  browser's microphone indicator being lit for exactly as long as a button
 *  is held is the only honest signal a customer can actually check. */
export function useDictation({ onText }: { onText: (text: string) => void }): Dictation {
  const [recording, setRecording] = useState(false);
  const [error, setError] = useState("");
  const recRef = useRef<MediaRecorder | null>(null);
  const streamRef = useRef<MediaStream | null>(null);
  const chunks = useRef<Blob[]>([]);

  // Every exit path goes through here, including the failures. See trap two.
  const release = useCallback(() => {
    streamRef.current?.getTracks().forEach((t) => t.stop());
    streamRef.current = null;
    recRef.current = null;
    setRecording(false);
  }, []);

  const start = useCallback(() => {
    if (recRef.current) return;
    setError("");
    chunks.current = [];
    void (async () => {
      let stream: MediaStream;
      try {
        stream = await navigator.mediaDevices.getUserMedia({ audio: true });
      } catch {
        setError("Guardian could not use the microphone. Check the browser's permission for this site.");
        setRecording(false);
        return;
      }
      streamRef.current = stream;
      const mime = pickMime();
      const rec = new MediaRecorder(stream, mime ? { mimeType: mime } : undefined);
      recRef.current = rec;

      rec.ondataavailable = (e: BlobEvent) => {
        if (e.data && e.data.size) chunks.current.push(e.data);
      };
      rec.onstop = () => {
        const type = rec.mimeType || mime || "audio/webm";
        const blob = new Blob(chunks.current, { type });
        void (async () => {
          try {
            if (!blob.size) return;
            const form = new FormData();
            form.append("file", blob, "clip");
            const res = await fetch("/api/v1/voice/transcribe", {
              method: "POST", credentials: "include", body: form,
            });
            if (!res.ok) {
              setError(res.status === 503
                ? "Voice is not configured on this hub."
                : "Guardian could not make out that recording.");
              return;
            }
            const text = ((await res.json()) as { text?: string }).text ?? "";
            if (text) onText(text);
            else setError("Guardian heard nothing in that recording.");
          } catch {
            setError("Guardian could not reach the hub to transcribe that.");
          } finally {
            release();
          }
        })();
      };

      rec.start();
      setRecording(true);
    })();
  }, [onText, release]);

  const stop = useCallback(() => {
    const rec = recRef.current;
    if (!rec) { release(); return; }
    try {
      if (rec.state !== "inactive") rec.stop();   // `onstop` does the rest
      else release();
    } catch {
      release();
    }
  }, [release]);

  return { recording, error, start, stop };
}
```
