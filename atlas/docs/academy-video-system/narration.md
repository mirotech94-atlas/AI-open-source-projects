# Narration: sound like a person

Every Atlas episode is spoken by a human at a human pace. The visual system only works if the voice gives the viewer time to look where the motion points.

## Pace

- One idea per sentence; one sentence per action. Say what you are about to click, click it, then say what happened.
- Target 130–150 words per minute for explanation and slower (110–120) when reading a value, a node name or code aloud. Never above 160.
- Breathe at the cut. A natural inhale between steps is kept, not trimmed; only repeated starts, filler and dead waiting time are removed.
- After every CheckpointTag, stop talking for 2–3 seconds (`hold-tag`) so the viewer can compare their screen with yours.
- After a definition, pause one beat before the next action. After an error appears, pause before naming the cause; the viewer needs a moment to read it.
- Read the "Pause and try it" prompt, then actually stop for 3 seconds before cutting to the answer shot.

## Plain and direct

- Lead with the point: "This node sends the inquiry to Claude." Then the detail. Never "so basically what we're going to be doing here is".
- Use the product's own words for controls and nodes, and everyday words for everything else. Define a term the first time it appears, in one sentence, with the glossary card on screen.
- Say numbers, costs and prerequisites exactly. If something costs money or needs an account, say it before the step, not after.
- One "you" per sentence. No "guys", no "let's go ahead and", no rhetorical questions stacked before the answer.
- Say when you don't know or when something failed. The ErrorRecovery card exists because the mistake stayed in.

## Delivery

- Record sitting, with the script as bullet points, not read word for word; a read script sounds read.
- Keep the first take's energy for the opening line; re-record only sentences, not whole sections, so the pace stays even.
- No pitch-shifting, heavy compression or AI voice processing; light noise reduction and a gentle level only. If a synthetic voice is ever used, say so in the description.
- Music, when used, sits under the brand sting and the end card only, ducked to nothing beneath explanations.

## A scripted sample (opening, ~20 s)

"Here is the result. — An inquiry came in, and the workflow wrote this draft. — Nothing is sent yet; you check it first. — In this lesson we build the draft step, then test the hand-off to review. — You'll need an n8n account and a Claude API key. — Start by opening the Claude node."

Each dash is a breath or a beat, 0.5–1 s. The whole opening sits over ResultTitle → WorkflowTrace → BrandSting → the real app.
