## How they open

n8n's own video opens with the maker's name and one promise: the key
ideas of agent-style automation, built as a question-and-answer bot in two
parts. It states what you need up front (a running n8n and an LLM key) and
says it assumes a little technical comfort. Kevin Stratvert opens with a small
business problem, chasing late-paying customers, and spends the first minutes
defining what an agent is before touching the editor. Nate Herk opens already
on the canvas with the finished goal, a WhatsApp bot that answers customers,
and goes straight to credentials. None opens on the agent node itself.

## The order they explain things

- n8n's video: a web form feeds a data table (an ingest flow), then a second
  workflow adds a chat trigger and an agent, a chat model, memory and a tool
  that reads the table, then a system message, then testing, and finally the
  list of past runs. The agent comes last, after the data it will use.
- Kevin Stratvert: what an agent is (reasoning, tools, memory), free setup,
  then model, memory and tools in that order, a prompt structured in
  sections, a structured output, an approval step through a chat app, and a
  weekly schedule instead of a chat start.
- Nate Herk: the trigger's credential made at the provider first, the send
  node's separate credential second, an agent in the middle, and finally the
  agent's reply mapped into the outgoing message.

## Examples and analogies

- The system message as the manual the agent follows; the default says it is
  a helpful assistant, which is not enough once a tool exists (n8n's video).
- A tool's description as the thing the model reads to decide when and how to
  use it (n8n's video).
- An agent defined as three traits, reasoning, tool access and memory, set
  against a chatbot that only follows given steps (Kevin Stratvert).
- A late-payer chaser as the running example, with a person approving each
  email before it goes (Kevin Stratvert).

## Beginner mistakes they address

- An agent with no instruction to use its data will invent answers; the fix
  is a system message that says to admit when nothing was found (n8n).
- The agent errors on the first chat because model, memory and tools are not
  attached yet (Kevin).
- The model sends a made-up value to a tool and the tool step fails; tighten
  the prompt and try again, several rounds are normal (Kevin).
- Two different credentials for the trigger and the sender, easy to mix up
  (Nate).
- A workflow that is not switched on only listens while you press execute
  (Nate).
- A public number anyone can message can run up model costs (Nate, briefly).

## Pacing

n8n's video runs about 228 words a minute across nearly 21 minutes, with
chapter markers and little repetition. Nate Herk is the fastest at about 273,
a credential walk-through with almost no explanation of why. Kevin Stratvert
is the calmest at about 190, with the longest conceptual opening and a clear
recap at the end. All three start doing something on screen within about a
minute.

## What they do badly, and what we do better

- Two of the three are build-along projects needing outside accounts (a
  business messaging platform, accounting software, a chat app) that a
  beginner may not have. Our lab needs only n8n and one model credential.
- None isolates the proof that a tool was actually called; viewers read the
  answer and trust it. We turn on the intermediate steps and read them.
- Approval is shown only by Kevin, mid-project. We make it its own exercise
  and show both outcomes, approve and deny.
- Nate's video drifts from our topic: it is about messaging-platform
  credentials, with the agent as a prop. We take nothing from it except the
  warning about open public inboxes.
- The long videos teach a pile of ideas at once; ours is three exercises.

## What we take (structure only)

1. Show the agent doing something, not just talking.
2. Treat the system message and the tool wording as part of the build.
3. Prove behaviour in the run log, not in the reply text.
4. Memory as a short exercise: say a name, ask for it back.
5. A person approving risky tool calls, with deny shown as clearly as approve.
6. Say plainly that agents can invent values and that a few retries are normal.
