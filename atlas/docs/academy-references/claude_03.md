- https://www.youtube.com/watch?v=O_z9vDLgvoY -- Kevin Stratvert, 113,332 views, 14:32, read 2026-10-18. 202 words/min; first on-screen action at 16 s (transcript heuristic); 10 chapters.
- https://www.youtube.com/watch?v=O6tQ6V_P8a0 -- Tristen O'Brien, 100,851 views, 6:59, read 2026-10-18. 235 words/min; first on-screen action at 100 s (transcript heuristic); 8 chapters.

## How they open

All three are about skills in the Claude apps first; only the second Kevin
Stratvert video spends real time on Claude Code. The older Stratvert video
opens on the release news and a promise list (built-in skills, your own,
connecting apps), then a paid-plan check before anything is built. The 2026
Stratvert video defines a skill in one line in its first seconds, names the
three places it will run, and states the one skill it will build together.
Tristen O'Brien opens on the pain (retyping the same instructions), lists
what the video will cover, and teases a data-safety warning for the end.
None shows a finished skill running before the explanation starts.

## The order they explain things

- Stratvert (first): plan check and settings toggles, a built-in skill run
  (a deck from an outline, then restyled by a second skill), building one
  with the skill-creator through its questions, downloading and uploading
  the file, running it, editing it by prompt, then a mail-connected skill.
- Stratvert (2026): what a skill is (a saved prompt in a Markdown file,
  sometimes with code), create one with the skill-creator, the header versus
  the body, test against a real example, save, the two ways it triggers, run
  it by slash name, then the desktop apps, then Claude Code (global versus
  project folders, copying the folder in, a new session to pick it up), then
  four ways to share: zip, organisation skills, a synced drive, version
  control.
- O'Brien: the problem, a deliberately jargon-heavy definition followed by
  the plain one, the toggle that lets skills run, the built-in directory and
  plugins, the skill-creator, a live small-business example, the safety
  warning about third-party skills, then cost.

## Examples and analogies

- A deck from a text outline, restyled with brand colours by a theme skill
  (Stratvert, first).
- A "should I care about this AI tool" summariser with a score (Stratvert).
- An email-thread catch-up skill: summary, action items and a draft reply in
  the user's tone (Stratvert, 2026).
- A payroll sanity check from an exported PDF, used as the sponsor segment
  (Stratvert, 2026).
- A pizza shop turning a vague catering email into a priced quote, then a
  quick list of other trades that could do the same (O'Brien).
- A skill described as a saved prompt that only loads when needed, so many
  can be installed at once (Stratvert and O'Brien).

## Beginner mistakes they address

- Not answering the creator's follow-up questions, or not asking it what
  else it needs to know; both videos by Stratvert treat this as the step
  that decides quality.
- Relying on automatic triggering; both Stratvert videos say calling the
  skill by name is more dependable.
- Expecting a skill made in the web app to appear in Claude Code; it has to
  be copied into the right folder, and a new session started.
- Moving the single file instead of the whole skill folder.
- Sharing by sending copies, so two people end up on different versions.
- Installing skills found online without reading them first (O'Brien).
- Leaving off the setting that lets skills run code (O'Brien).

## Pacing

Measured above: from about 167 to 235 words a minute, with the first
on-screen action between 16 s and 100 s. The fastest talker (O'Brien) also
takes longest to touch the screen because the first minute and a half is
problem and definition. The Stratvert videos stay in the app and narrate
each click, and fast-forward through waits. Chapter names are mostly
descriptive; the first Stratvert video has generic ones (Intro, Tutorial
Starts, Outro). Two of the three carry a sponsor read in the middle of the
teaching, and one asks for likes mid-demo.

## What they do badly, and what we do better

- Almost no time on the actual file: the header, the description that
  drives triggering and the folder layout are mentioned and passed over.
  We open the SKILL.md on screen and read each part once.
- Claude Code is an afterthought in all three. Our episode is built in
  Claude Code from the first minute.
- Sponsor segments sit in the middle of the build. We have none.
- The jargon-on-purpose definition makes a point but loses beginners for a
  minute. We give the plain definition first and the precise one second.
- The safety warning cites a statistic without a source. We say read every
  third-party skill before installing it, and we do not quote numbers we
  cannot point to.
- Generic chapter names in one video. Ours name the file or the step.

## What we take (structure only)

1. Name the pain of repeating the same instructions, then the one skill we
   will build, in the first seconds.
2. Show where skills live (personal versus project folder) before writing
   one.
3. Build one small skill end to end, then run it by name and by context.
4. Test it on a real example and change it once on camera.
5. Close on a safety habit: read a skill before installing it.
