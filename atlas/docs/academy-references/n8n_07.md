## How they open

n8n's own developer advocate opens with a one-line promise (n8n on your own
computer through Docker Desktop) and is at the download page in seconds.
NetworkChuck opens on who the video is for, home lab or rented server, and
sends newcomers to another video first. Lawrence Systems opens on a
licensing caveat (source available, not a classic open source licence),
then the version he is targeting. None shows the editor running first.

## The order they explain things

- n8n's video: pick the right Docker Desktop download for the chip, install
  it, find your time zone, create a data volume and why it keeps your work
  across upgrades and reboots, pull the image, set the container's port,
  volume and environment values in the desktop app, open the editor.
- NetworkChuck: why outside services can't reach a machine behind a home
  firewall, a domain and a tunnel to fix that, Docker installed from the
  official repository, then n8n's compose files with an env file, start
  detached, check the running containers, open the site.
- Lawrence Systems: his own compose and env files, folders created ahead
  for the right permissions, the first start run attached to watch the
  messages, the database built on first run, the owner sign-up, a template
  imported, and a pointer to a reverse proxy.

## Examples and analogies

- The volume as the place your workflows live, so the program can be
  replaced without losing them (n8n's video).
- n8n described as a very social program that wants to connect to things,
  as the reason home hosting gets tricky (NetworkChuck).
- A backup-your-workflows template as the first thing to import (Lawrence).

## Beginner mistakes they address

- Downloading the wrong Docker build for the machine's chip.
- Skipping the volume, then losing workflows on an update or restart.
- Wrong time zone, so schedules fire at odd hours.
- Webhooks from outside services not reaching a local install.
- Bind-mount folders created by Docker with the wrong permissions.
- Starting detached the first time and missing the error messages.

## Pacing

n8n's video is short and brisk, about 171 words a minute, and stays on one
path. NetworkChuck runs about 210 with jokes and coffee breaks, and spends
the first half on domains and tunnels before n8n appears. Lawrence is quick
and assumes Docker knowledge.

## What they do badly, and what we do better

- Two of the three teach a manual setup that n8n's own docs now mark as
  outdated, or a hand-edited compose file. We teach the one-line setup the
  docs lead with, which writes the compose file for you.
- NetworkChuck's first half is a paid domain and a third-party tunnel. We
  stay local and say only n8n's own port is reachable from outside.
- None warns that one stop flag deletes the data volume. We make that the
  key warning of the lesson.
- None says plainly when Cloud is the better choice. We repeat n8n's own
  advice: self-hosting suits people used to running servers.

## What we take (structure only)

1. Open on the editor at its local address.
2. The choice first: Cloud or self-hosted, in two lines.
3. Get Docker, then one setup command, then open the editor.
4. Explain the volume as where the work lives, with the one flag that
   deletes it.
5. Upgrades that keep the data, then a lab that proves the install.
