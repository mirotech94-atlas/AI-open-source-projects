## How they open

Michele Torti opens on fear: the topic scares beginners, it scared him, and
it is easier than it looks, then spends a long stretch on data basics before
any node. David Ondrej opens with a bold claim that this is the most powerful
node and most people never use it, then shows how to add it in seconds. Jono
Catliff opens with a similar claim, that very few builders use it, and
promises a no-coding-needed walk-through with a deployment at the end.

## The order they explain things

- Michele Torti: what JSON is, key and value pairs, lists, nested objects,
  how APIs use it, then a worked edit-fields example, and a branch on a
  value. The code node is barely part of it; the first on-screen action comes
  late, around the fourteen-minute mark.
- David Ondrej: what the node is, JavaScript versus Python, using AI to
  write the code, the shape of input and output, then four practical cases
  (grouping orders by customer, a media upload the built-in node cannot do,
  filtering an API response, reading nested JSON), a sponsor segment on
  hosting, and finally when not to use it.
- Jono Catliff: why it matters, a spreadsheet of leads as the running case
  (sorting, regrouping JSON, making IDs, cleaning a transcript, nested
  filters), then asking a chat assistant for the code, pasting it in, and
  fixing errors by pasting the error back.

## Examples and analogies

- A shopping list as the picture of a list of items under one name (Michele).
- JSON called English for computers (Michele).
- A thousand messy orders turned into one sentence per customer with the
  total spent (David).
- A leads sheet sorted by price, high to low, after one request (Jono).
- Pasting the error text back to the assistant to get a fixed version (Jono).

## Beginner mistakes they address

- Using code where a built-in node would do: a wait node for a pause, the
  loop node for repetition (David).
- Mixing up text and numbers: a value in quotes is text (Michele).
- Pasting code that errors and not knowing what to do; give the error back
  to the assistant (Jono).
- Believing the assistant's code is right without running it on real items
  (implied by Jono's retries).
- Treating the node as the first option; Jono himself says he would use the
  built-in tools first.

## Pacing

Michele Torti is about 212 words a minute over eleven chapters, heavy on
theory before action. David Ondrej is about 207 across fourteen chapters and
24 minutes, with a sponsor break in the middle. Jono Catliff is shortest at
about 14 minutes, fast and repetitive, with a sales pitch at the end.

## What they do badly, and what we do better

- Jono leans on pasted AI-written code and never explains the return
  format the node insists on; David touches it briefly. We teach that rule
  directly.
- Only David mentions the two run modes, in passing. We make all items or
  each item the first decision.
- Michele's video is mostly a JSON primer and drifts from our topic; we take
  only the idea that values have types.
- The sponsor and community pitches take minutes in two videos.
- Claims like it never breaks or costs nothing are not backed. We say what the
  node cannot do (files, requests, credentials) from the docs.
- We make the lesson's point out loud: code last, built-in nodes first, and
  we hold the lab to a non-code solution first.

## What we take (structure only)

1. Open with the promise that this is the escape hatch, not the first tool.
2. Say what it is for: jobs the built-in nodes cannot do.
3. Short example of the item format returned.
4. Show a thing code cannot do, so beginners do not hit it blind.
5. Name the common built-in replacements: wait, loop, expressions.
6. Offer assistant-written code as an option, but say to read and run it.
